Errors and limits

Every error has the same shape and an HTTP status. Branch on error.code, not on message.

Error object

{
  "error": {
    "code": "SPLIT_MISMATCH",
    "message": "Exact shares must add up to the amount",
    "details": {
      "difference": "0.50"
    }
  }
}

details appears only on some errors: SPLIT_MISMATCH (difference), OVERPAY (youOwe, theyAreOwed), agent caps (limit, spent, window) and NEEDS_REVIEW (txHash).

Settlement verification codes

When you record a settlement, the API checks the transaction on Horizon. A failed check answers 422 with one of these codes (on the x402 route, a fresh 402 with the code in error).

CodeMeaning
PAYMENT_NOT_FOUNDTransaction not found on Stellar Testnet. Wait for it to land, then retry
PAYMENT_FAILEDThe transaction failed on chain
INTENT_MISMATCHThe memo does not match the intent
TIMEBOUNDS_TOO_LONGThe transaction may land after the intent expires. Set its max time to expiresAt or earlier
PAYMENT_MISMATCHNo payment in the group asset with this payer, payee and amount
WRONG_NETWORKThe server's Horizon is not Testnet

Rate limits

The only rate limit in the code is on the receipt scan: 10 scans per person per 10 minutes, counted per serverless instance. Over it, 429 RATE_LIMITED. The API sends no rate-limit headers and no Retry-After.

async function withRetry(fn, tries = 4) {
  for (let i = 0; i < tries; i++) {
    const res = await fn();
    if (res.status !== 429 && res.status !== 502) return res;
    await new Promise((r) => setTimeout(r, 2 ** i * 1000)); // 1s, 2s, 4s, 8s
  }
  throw new Error('gave up after retries');
}
import time

def with_retry(call, tries=4):
    for i in range(tries):
        res = call()
        if res.status_code not in (429, 502):
            return res
        time.sleep(2 ** i)
    raise RuntimeError("gave up after retries")
Fair use

Other routes have no limit in the code. Vercel's platform limits still apply. Keep polling gentle.

Body limits

  • 64 KB for every body, except the receipt scan (1.4 million base64 characters of photo).
  • Over the limit: 413 with a JSON error, and the connection closes.
  • Bodies must be JSON objects. Arrays, null or invalid JSON: 400 VALIDATION.

Idempotency

POST /v1/groups/:id/expenses accepts an Idempotency-Key header (8 to 64 of A-Z a-z 0-9 - _). A repeat with the same key in the same group returns the first expense and creates nothing. Use one key per form submission. Settlements are idempotent by transaction hash: a hash is recorded once, a repeat gets 409 DUPLICATE_TX.

What is safe to retry

  • 502 UPSTREAM_UNAVAILABLE: yes, with backoff.
  • 422 PAYMENT_NOT_FOUND right after submitting: yes, after a few seconds.
  • POST .../expenses: yes, with the same Idempotency-Key.
  • A signed payment: never sign a second payment for the same intent. Record the first hash.

Versioning

All routes are under /v1. There is no other version today. Fields may be added to responses, so ignore fields you do not know.
